# Портфолио Арнура

Многостраничное портфолио junior frontend-разработчика из Казахстана. Сайт работает на Next.js
App Router, React и TypeScript strict.

**Стили:** CSS Modules изолируют карточку проекта; цветовые токены и общие правила лежат в
`src/app/design.css`, оформление главной страницы — в `src/app/home.css`.

В портфолио нет придуманных отзывов, клиентов или результатов. Все три примера прямо помечены как
учебные концепты.

## Запуск на компьютере

Нужен Node.js версии 22.13 или новее.

```bash
npm install
npm run dev
```

Откройте <http://localhost:3000>. `next dev` запускает только интерфейс, без серверных маршрутов.
Чтобы проверить Pages Functions с локальной D1, соберите сайт и выполните
`npx wrangler pages dev out --d1 ADMIN_DB=YOUR_DATABASE_ID`. Wrangler возьмёт тестовые секреты из
`.dev.vars`; локальная база хранится отдельно от удалённой. Вместо `YOUR_DATABASE_ID` укажите
ID базы, который Wrangler показывает после её создания.

Проверки проекта:

```bash
npm run typecheck
npm run lint
npm run format:check
npm run build
```

## Отправка заявок

Заявки отправляет Cloudflare Pages Function на FormSubmit, используя адрес `contactEmail` из
`src/data/contact.ts`. При первой отправке FormSubmit присылает владельцу адреса письмо для
активации формы. Откройте его и подтвердите адрес; проверьте папку «Спам», если письма нет. До
подтверждения сервис хранит заявки и отправляет их после активации.

Путь заявки: пошаговая форма → проверка Zod в браузере → `POST /api/contact` → повторная проверка
Zod на сервере → honeypot и ограничение частоты → сохранение в D1 и отправка FormSubmit. Если
почтовый сервис временно недоступен, сохранённая заявка остаётся в админке.

Ограничение частоты запросов хранится в памяти экземпляра Cloudflare Function и может сброситься
между запросами. Для надёжного общего лимита используйте Cloudflare Durable Objects или другое
общее хранилище.

## Админка и база заявок

Откройте `/admin`. Первый вход создаёт начальную учётную запись из переменных
`ADMIN_BOOTSTRAP_USERNAME` и `ADMIN_BOOTSTRAP_PASSWORD`, после чего пароль сохраняется только в
виде PBKDF2-хэша. Используйте новый уникальный пароль длиной от 14 символов; пароль из переписки
не используйте. Сессия хранится в D1, а браузер получает только HttpOnly cookie.

Чтобы включить админку в Cloudflare:

1. Выполните `npx wrangler login`, затем `npx wrangler d1 create arnur-portfolio-admin`.
2. В Cloudflare Pages откройте Settings → Bindings → Add → D1 database. Назовите binding
   `ADMIN_DB` и выберите созданную базу.
3. Примените миграцию: `npx wrangler d1 migrations apply arnur-portfolio-admin --remote`.
4. Добавьте два секрета командой
   `npx wrangler pages secret put ADMIN_BOOTSTRAP_USERNAME --project-name arnurmedetuly777-portfolio`
   и аналогичной командой для `ADMIN_BOOTSTRAP_PASSWORD`. Wrangler запросит значения отдельно;
   пароль не передавайте аргументом команды и не отправляйте в чат.
5. Повторно запустите deployment в Cloudflare Pages. После этого откройте `/admin` и войдите.

В админке доступны список последних 200 заявок, фильтр по статусам, заметки и изменение статуса.
Добавлять администраторов и отзывать их доступ может только владелец; другие администраторы работают
с заявками. Удалить самого себя или последнего администратора нельзя. Новый администратор задаёт
пароль при создании, поэтому передайте ему логин и временный пароль лично. FormSubmit хранит только
почтовые отправки; заявки, сделанные до подключения D1,
в админке автоматически не появятся.

Локальный пример переменных лежит в `.dev.vars.example`. Скопируйте его в `.dev.vars` и задайте
уникальный тестовый пароль. Создайте D1 в Cloudflare, возьмите его ID из вывода Wrangler и
передайте его параметром `--d1 ADMIN_DB=<DATABASE_ID>` при запуске Pages Functions. Эта команда
использует локальную копию базы. Не коммитьте `.dev.vars`.

## Публикация на Cloudflare Pages

1. Выберите ветку `main`, build command `npm run build` и build directory `out`.
2. Добавьте `NEXT_PUBLIC_SITE_URL=https://arnurmedetuly777-portfolio.pages.dev` как build variable.
3. Подключённый Git-репозиторий создаёт deployment после push; вручную запустить его можно командой
   `npm run pages:deploy` после входа в Wrangler через `npx wrangler login`.

Next.js создаёт sitemap и robots по адресам `/sitemap.xml` и `/robots.txt`. После публикации
проверьте адреса и добавьте sitemap в поисковые панели, если это нужно.

## Как устроен код

```text
src/
  app/                  страницы Next.js, metadata и статический экспорт
    projects/[slug]/    страница отдельного проекта
    blog/[slug]/        страница MDX-заметки
  components/           общие карточки, оболочка, фильтры и калькулятор
  content/blog/         тексты заметок в MDX
  data/                 редактируемые данные сайта и словарь интерфейса
migrations/             схема Cloudflare D1
functions/api/          Cloudflare Pages Functions для заявок и админки
  admin/                авторизация, сессии, заявки и администраторы
  lib/                  схема формы и небольшие общие функции
  types/                типы MDX
```

Полезно смотреть файлы в таком порядке:

1. `src/app/page.tsx` — главная. JSX — это описание того, какие элементы увидит посетитель.
2. `src/data/site.ts` — профиль, проекты, шаги работы и FAQ. Тексты здесь можно менять без правок
   в компонентах.
3. `src/components/ProjectCard.tsx` — карточка, которую используют главная и список проектов.
4. `src/components/ProjectsExplorer.tsx` — поиск, фильтры и сортировка. `useState` хранит выбор
   пользователя, `useMemo` пересчитывает список при изменениях.
5. `src/data/pricing.ts` и `src/components/PricingCalculator.tsx` — таблица цен и интерактивный
   расчёт. В компоненте можно проследить, как выбранные услуги складываются в диапазон цены.
6. `src/lib/contact-schema.ts`, `src/app/contact/ContactForm.tsx` и
   `functions/api/contact.ts` — одна схема полей, форма и серверная проверка/отправка.
7. `src/content/blog/*.mdx` — обычный Markdown с заголовками и списками; конфигурация в
   `next.config.ts` подключает эти файлы к Next.js.
8. `src/app/design.css` — общий визуальный язык, адаптивность и состояния фокуса.

**`page.tsx`** в папке `src/app` задаёт страницу: например `src/app/about/page.tsx` открывается
по адресу `/about`. Папка `[slug]` означает динамическую часть URL, например
`/projects/sary-arqa`.

**`'use client'`** нужен компонентам, которые используют состояние, события или API браузера.
Статичные страницы остаются серверными. **TypeScript** помогает ограничить допустимые варианты
значений, а **Zod** проверяет ввод и в браузере, и на сервере: клиентскую проверку можно обойти,
поэтому сервер проверяет данные заново.

Русский язык включён по умолчанию. `src/data/messages.ts` содержит словарь для RU/KZ/EN как
заготовку; полноценные переводы страниц пока не подключены.

## Шрифты и изображения

Используется системный шрифт, которому не нужна сетевая загрузка. Изображения проектов хранятся
локально в `public/projects/`. Страница `/sources` содержит лицензии фотоматериалов; перед заменой
фотографий проверьте лицензию каждого нового изображения.
